# Pomo 3.0.0 · 任务专注

## 迭代分析

Pomo 已经能记录三类信息。今日任务回答「要做什么」，计时和时间块回答「完成了多少」，7/30/90 天复盘回答「什么时候投入了时间」。上一版没有同时记录任务身份与完成的番茄，因而无法回答一个具体问题：「这周花了多少时间处理这项任务？」

三端已经有自然日统计、独立任务数据和统一的复盘口径，可以用现有页面完成这个流程。任务按钮进入原有计时引擎，计时阶段捕获任务 ID、标题和设定时长，成功完成时将用时明细和日统计写进同一个 JSON。已有记录继续用于原有统计。只用任务标题跨天汇总会合并同名的不同任务，因此复盘用稳定 ID 聚合，显示区间内最后一次快照的标题。

日总数与任务明细随同一次原子写入落盘，减少了应用退出时两边记录不一致的机会。旧历史缺少任务身份，仍计入复盘总量；只有明确从任务启动并完成的番茄会计入任务用时。

## 使用与数据规则

1. 在「任务」页点今日未完成任务的播放图标，应用切到专注页并开始计时。正在运行或暂停的番茄需要先结束，才能启动另一项任务；在休息阶段点击会立即开始下一轮。
2. 成功完成时按番茄到期的自然日记账，使用开场时捕获的标题和分钟。任务的勾选仍由用户决定。暂停后继续保留任务；放弃和跳过清除当前关联。
3. 在「专注复盘」查看日期范围内或选中当天的任务用时，按分钟从高到低显示。关联比例以完成的番茄数为分母，包含此前只记总数的记录。任务 CSV 每行对应一个完成的任务番茄，含日期、任务 ID、标题与分钟。

Task 使用时间块定义的逻辑日，番茄及其任务用时使用自然日。跨午夜的一个番茄归入到期当天。原有汇总 CSV 字段和日界保持原样。清空番茄统计时一起删除任务用时，保留任务、时间块和植物记录。

## 升级与验证边界

- macOS 3.0.0 build 20、iOS 3.0.0 build 7、Android 3.0.0 versionCode 8。
- Mac/iPhone 共用同一数据目录时，应先将两端升到 3.0.0 再继续使用该目录。旧版能读取日总数，但改写统计文件会丢弃任务用时字段。同目录合并只针对设备当前可见的文件修订。
- Android 将任务快照随计时状态保存，恢复已记账的任务番茄时按会话 ID 去重。Apple 平台仍使用应用运行期间的计时状态。
- Android 专注明细存于本机。Habitica 仍通过现有接口同步任务和计分。
